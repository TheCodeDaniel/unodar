# Unodar Dart subset — Phase 1 (0.1, experimental)

This is the **exact** list of what the compiler accepts. Anything not listed here is rejected with a diagnostic
(see [`DIAGNOSTICS.md`](DIAGNOSTICS.md)). The subset grows phase by phase; this file is updated *before* any new
syntax is accepted.

## A complete valid program

```dart
import 'package:unodar/unodar.dart';

void setup() {
  pinMode(13, OUTPUT);
}

void loop() {
  digitalWrite(13, HIGH);
  delay(500);
  digitalWrite(13, LOW);
  delay(500);
}
```

## Accepted

| Construct | Rule |
|---|---|
| Imports | Exactly `import 'package:unodar/unodar.dart';`, without `as`, `deferred`. `show`/`hide` are allowed. |
| `library;` directive | Allowed and ignored. |
| Top-level declarations | Only `void setup()` and `void loop()`. **Both are required.** |
| Entry point signature | Return type written as `void`; no parameters; no type parameters; a `{ … }` block body; not `async`/`sync*`/`external`, not a getter/setter. |
| Statements (inside `setup`/`loop`) | Only a single call statement: `name(arg, …);` |
| Callable functions | `pinMode(pin, mode)`, `digitalWrite(pin, value)`, `delay(ms)`, declared in `package:unodar`. A function with the same name from anywhere else is not accepted. |
| Arguments | Non-negative integer literals (`13`, `500`, `0x0D`), and the unodar constants `HIGH`, `LOW`, `OUTPUT`, `INPUT`, `INPUT_PULLUP`. |
| Comments | Anywhere; ignored. |
| Empty bodies | `void loop() {}` is fine. |

## Translation

| Dart | C++ |
|---|---|
| `void setup() { … }` / `void loop() { … }` | The same function, preceded by `#line <n> "<file>.dart"` |
| `pinMode(13, OUTPUT);` | `pinMode(13, OUTPUT);` preceded by its own `#line` |
| Integer literal (any notation) | Its decimal value, e.g. `0x0D` → `13` |
| Constant (`HIGH`, …) | The Arduino macro of the same name |

The generated file starts with a `// Generated by unodar…` comment and `#include <Arduino.h>`. Output is
deterministic: the same input gives byte-identical output on any machine.

**Integer range:** literals are emitted as written, with no range check. How Dart `int` maps to C++ integer types
on the 16-bit AVR is an open decision for Phase 2 (PRD §13.1). Until then, keep values within what the Arduino
function accepts (e.g. `delay` takes an `unsigned long`).

## Rejected (non-exhaustive)

| Construct | Code |
|---|---|
| Missing `setup()` or `loop()` | E001 |
| `if`, loops, `return`, local variables, blocks, `switch`, … inside `setup`/`loop` | E002 |
| Calls to anything other than `pinMode`/`digitalWrite`/`delay` (incl. your own functions, `Serial.println`) | E003 |
| Arguments that are expressions, variables, negative numbers, strings, bools, doubles | E004 |
| Top-level variables, classes, enums, extra functions, typedefs, other imports, `export`/`part` | E005 |
| `setup`/`loop` with parameters, a non-`void` or missing return type, `=>` body, `async` | E006 |
| Any Dart analysis error (type errors, syntax errors, unresolved imports) | E007 |
| `main()` (reserved for the Phase 4 widget API) | E008 |
| Strings, `Serial`, widgets, `Signal`, classes, interop annotations, `cpp()` | not yet available |
