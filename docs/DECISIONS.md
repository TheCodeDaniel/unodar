| 2026-11-10 | Diagnostic locations and `#line` directives use the source file's basename, not an absolute path. | Output must be byte-identical across machines (determinism, goldens). Matches the PRD's `#line 3 "blink.dart"` example. |

| 2026-11-11 | **PRD §13.1 decided by the maintainer:** Dart `int` → `int32_t`, `double` → `float`, `bool` → `bool` on every target. Sized `Uint8`/`Uint16`/`Int16` extension types in `package:unodar` map to `uint8_t`/`uint16_t`/`int16_t`. | One `int` width on Uno and ESP32 keeps programs portable, and 32 bits covers `millis()`-style values. Overflow behaviour differs from Dart's 64-bit `int` and is documented in SUBSET.md "Known deviations from Dart". |
| 2026-11-11 | Sized types are `extension type const Uint8._(int) implements int` with a wrapping `const Uint8(int v)` constructor. Reading widens to `int`; arithmetic yields `int`; storing back needs an explicit `Uint8(...)`. | The Dart side is real, executable, and tested, and it wraps exactly like the C++ conversion. Making implicit truncation a Dart type error means a value never changes width invisibly. |
| 2026-11-11 | `/` on ints is **implemented** as `float(a) / float(b)` (a `double` result, as in Dart), not rejected. | Dart's type checker already forbids storing the result in an `int` (E007, suggesting `~/`), so the C mistake of truncating division cannot happen silently. Precision is the documented `double` → `float` deviation. |
| 2026-11-11 | `~/` on ints compiles to C++ `/`; `%` on ints compiles to a `constexpr unodar_mod(a, b)` helper with Dart's non-negative result, emitted only when used. `%`/`~/` on doubles are rejected (E002). | Both C++11 and Dart truncate `~/` toward zero. Rejecting `%` would break the common `i % 2 == 0`. A helper inside the `.ino` keeps single-file output (PRD §13.2 untouched); `constexpr` keeps it usable in constant initializers. |
| 2026-11-11 | The IR holds expression trees without parentheses; the emitter inserts them from C++ precedence and associativity. | The Dart parser's tree is the authority, so the output regroups correctly even where Dart and C++ precedence tables differ. |
| 2026-11-11 | Every `int` operation is computed in `int32_t`: when both operands would be narrower than 32 bits in C++ (literals and sized values on the 16-bit-`int` Uno), the emitter widens one with an `L` suffix or `int32_t(...)`. The native `int` width comes from the `Target`. | On AVR, plain C++ `60 * 1000` wraps to -5536. Widening only where needed keeps blink's output and most code unchanged. |
| 2026-11-11 | All-constant subexpressions are evaluated at compile time with Dart semantics; any intermediate value outside `int32_t`, or a constant division by zero, is E010. Runtime overflow and runtime division/`%` by zero are documented deviations with no checking helper (maintainer decision). | Catches every case that is knowable at compile time loudly; a runtime check would cost flash and invent behaviour Dart doesn't have on a device without exceptions. |
| 2026-11-11 | Assignments, `++`, and `--` are statements only (plus `for` updaters). Inside one operator's operands, one argument list, or the two sides of `+=`/`-=`, a user-function call may not sit next to another call or a read of a mutable top-level variable (E013). | Dart evaluates left to right; C++ leaves that order unspecified. | 2026-11-11 | Only `+=` and `-=` among compound assignments; `*=`, `~/=`, `%=`, and the bitwise forms are E002. Bitwise and shift operators are E002. | Matches the Phase 2 scope exactly. Shifts in particular differ (negative counts, counts ≥ 32, `>>>`) and need their own fidelity work. |
| 2026-11-11 | `==`/`!=` between a `bool` and a number is E009. | Dart: never equal. C++: `true == 1`. |
| 2026-11-11 | Dart `const` → `constexpr`, `final` → `const`, mutable → plain, for globals and locals.
